# agentLisp 用户故事地图

> 目的：把三线（投产 / AMS 搬迁 / RSI）的全部待开发 feature 落成用户故事。
> 结构：横向 = 用户旅程阶段（骨架）。纵向 = 故事，按发布切片分组。
> 来源：`agentlisp-master-plan.md`（37 工作项）+ `agentlisp-ams-feature-spec.md`（13 特性）+ `rsi-plan.md`（8 需求）。
> 基线：`05591eb`

---

## 0. 读法

| 项 | 约定 |
|---|---|
| **骨架** | 4 类用户 × 9 个阶段。横向读 = 一个用户的完整旅程 |
| **切片** | R1–R4。上片先做。同片内可并行 |
| **故事格式** | 作为〈用户〉，我要〈能力〉，以便〈价值〉 |
| **判据** | 每条故事给一条可判的验收。无判据不算故事 |
| **追溯** | 每条标来源（P 项 / F-AMS / FR-EVO） |

---

## 1. 四类用户

| 代号 | 用户 | 主要诉求 |
|---|---|---|
| **D** | Agent 开发者 | 写出能跑的 Agent |
| **O** | 运维者 | 跑起来、看得见、拦得住 |
| **M** | 工具维护者 | 加能力不变质 |
| **A** | 审计 / 决策者 | 说法与实现一致 |

**排序依据**：D 是主要用户。O 次之。M 与 A 是内部角色。

---

## 2. 骨架：9 个阶段

```
安装 → 创作 → 编译校验 → 运行 → 观测 → 验证 → 维护 → 发布 → 审计
```

**为什么这样切**：每阶段一个动作类型，互斥。

| 阶段 | 动作 |
|---|---|
| 安装 | 取得工具 |
| 创作 | 写 `.al` |
| 编译校验 | 编译器判对错 |
| 运行 | 产物执行 |
| 观测 | 看行为 |
| 验证 | 端到端取证 |
| 维护 | 改工具 |
| 发布 | 出制品 |
| 审计 | 查口径 |

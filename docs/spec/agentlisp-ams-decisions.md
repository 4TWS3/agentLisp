## 决策前的一处新实测（改变了 D2）

我原规格问「F-AMS-1 与 `:multiagent` 是否互斥」。查出约束后，这个问题问错了。

| 约束 | 证据 |
|---|---|
| `:multiagent` 在 KV 桶序中**固定为第 4 桶** | `.trae/specs/no_pypi_cr41_patterns_v2_1/spec.md:47` NFR-CR41-07 |
| `scoped-worker` 有必填四块校验 | `runtime/checker.py:335`、`rfc` 常量 `FR_PARSER_SCOPED_WORKER_REQUIRED_BLOCKS` |
| 有跨 worker 轨迹隔离测试 | `runtime/tests/test_srs_acceptance.py:1146` |
| 有必填块 SSOT 漂移测试 | `runtime/tests/test_harness_v2.py:1743` |
| 有 BDD 覆盖 | `tests/step_defs/test_bdd_suite.py` |
| **生产代码依赖** | 无。只有测试与规格 |

**结论**：`:multiagent` 的**声明层是有意设计、有测试守、有桶序约束**的。
它不是孤儿。孤儿只是运行期那两个变量（`_multi_workers` / `_multi_topology`）无人读。

所以正确动作不是「删掉其中一个」，而是「让运行期终于去读那个声明」。

另有一条独立证据支持同一判断：AMS 侧审计文档承认
PAT03 / PAT06 / PAT07 / PAT09 的语义「只以字符串形式存在于 `:system-prompt`，
Core AST 里没有任何可执行结构承载」。这与 agentLisp 的 8 个仅声明 kind 是同一病。

## D1 · F-AMS-13 多运行时输出：不搬，但设接口缝

### 决定

不搬 AMS 的 5 个 adapter。agentLisp 保持**单运行时**：产物继承 `BaseHarnessV2`。
但**定义一条运行时适配缝**：一个明确的协议，允许将来接第二个运行时。

### 理由（按权重）

| # | 理由 |
|---|---|
| 1 | 用户目标是「消除双工具与选型负载」。加 5 个运行时就是加 5 个选型维度，与目标相反 |
| 2 | 已生成的 langgraph 产物（`beidou/tianji`）**自包含**，不依赖 AMS。不需要 agentLisp 接管 |
| 3 | 维护不对称：AMS 那 4066 行 adapter 是为「生成代码给别人的框架跑」付的代价。agentLisp 的产物继承自己的 harness，这个代价不存在 |
| 4 | 真实需求面只出现 1 个运行时（langgraph）。为 1 个需求养 5 个 adapter 不成立 |

### 代价（必须告知）

- 已有 langgraph 产物**无法从 `.al` 再生成**。要改行为须手工改。
- 若将来确有第二个运行时需求，需新写 adapter。

### 为什么设接口缝

不加缝 = 把「单运行时」焊死进产物格式。将来要加就得改产物契约，代价高。
加缝 = 一个协议，零实现。成本小，保留可逆性。

**缝的形状**：产物只依赖一个窄接口（构造 + `run` + 观测回传），
不直接依赖 `BaseHarnessV2` 的具体内部。此项并入 F-AMS-6 重构一起做，不单列工作项。

### 判据

- 产物只 import 一个运行时符号面，且该面有协议定义；
- 反证：把该协议做第二个内存实现，产物不改一行即可跑。

### 翻转条件

出现第二个真实运行时需求（有具体消费方，不是「可能会用」）。届时重估。

## D2 · `:multiagent`：保留并内聚进 `:workflow`

### 决定

`:multiagent` **不删**。它与 F-AMS-1 的 `:workflow` 不是两套并列语法，而是**同一模型的两种入口**：

| 入口 | 语义 | 状态 |
|---|---|---|
| `:multiagent` | 多 agent 拓扑的**语法糖** | 声明层已有，运行期未接线 |
| `:workflow` | 通用图构造（含 `type: subagent` 节点） | 待建 |

**规则**：`defmultiagent` 展开为 `:workflow` + 子 agent 节点。不留两套执行语义。

### 理由

| # | 理由 |
|---|---|
| 1 | 它已有桶序约束（第 4 桶）、必填块校验、隔离测试、BDD。删掉是破坏 |
| 2 | 它的**声明层是好的**，坏的只是运行期没人读。修运行期，不删声明 |
| 3 | 保留它 = 保留「多 agent」这个高频用例的**短写法**。删掉则用户要手写 7 个 scoped-worker |
| 4 | 内聚到 `:workflow` 消除「两套执行语义」，符合用户「不要两个重叠能力」的诉求 |

### 代价

- `defmultiagent` 宏要重写为展开成 `:workflow`；
- 桶序约束（第 4 桶）要重述为新模型下的不变式；
- 相关测试要迁移。

### 判据

- 有测试断言：`defmultiagent` 与等价的显式 `:workflow` 产生**同一产物**（逐字节或结构同构）；
- `_multi_workers` / `_multi_topology` 不再存在，或由 `:workflow` 节点表取代；
- 跨 worker 轨迹隔离测试仍绿。

### 翻转条件

若 `:workflow` 的表达力无法覆盖 scoped-worker 的隔离语义，则退回并列语法并登记原因。

## D3 · F-AMS-6 槽位集合：采纳 8 + 1，并加防膨胀规则

### 决定

采纳规格提出的槽位。**9 个**，分两档：

| 档 | 槽位 | 运行时调用点 |
|---|---|---|
| 已实现（8） | `before_turn` / `on_tool_call` / `after_turn` / `order` / `budget` / `verify` / `evaluate` / `on_init` | 均已在 `PatternRuntime` / `BaseHarnessV2` 有调用 |
| 待实现（1） | `orchestrate` | F-AMS-7 的 `select_next` |

### 防膨胀规则（新增，重要）

> **槽位只能由运行时的调用点定义。** 新增槽位 = 新增一个真实调用点 + 一条断言。
> 禁止先加槽位再加实现。

**为什么加这条**：槽位表一旦成为「能力清单」，就会重演现在的病——
声明很多、发生很少。规则把槽位钉在运行时调用点上，从机制上防住。

### 判据

- `LANDED` 中每个 kind 的槽位集合非空；
- 每个槽位有对应的运行时调用点（有测试断言该调用点存在）；
- 判据脚本核对：槽位数 == 运行时调用点数。

### 翻转条件

无。此决策是架构骨架，且其判定依据（调用点）是客观事实。

## D4 · F-AMS-12 生成层：列入路线，排在 F-AMS-1~5 之后

### 决定

列入路线。**不现在做**，也不永久不做。
明确前置：F-AMS-1 至 F-AMS-5 全部完成。

### 理由

| # | 理由 |
|---|---|
| 1 | 现在不做：它含 LLM，非确定性。放编译期违反 C1；且现在做只能生成提示文本（因结构构造还不存在） |
| 2 | 不永久排除：它是 AMS 唯一「agentLisp 没有」的能力。排除它等于永久保留 AMS 的一角，与用户目标冲突 |
| 3 | 前置条件硬：没有结构构造，生成器只能产出把语义塞进 prompt 的产物。这已被 AMS 自己证明是弱化（见上「新实测」） |
| 4 | 它反哺验证：生成器产出的 `.al` 若不能过编译断言，说明语言表达力有缺口。它是**最难的用户** |

### 形态约束（现在写下，防将来走偏）

- 独立命令，**不在编译路径上**；
- 产物是 `.al` 草稿；
- 草稿必须过全部静态断言（F-AMS-1~5 的断言就是生成器的安全网）；
- 编译命令禁止引入 LLM 依赖（否则 CI 与可复现性断）。

### 判据

- 前置满足：F-AMS-1~5 的断言全部就位；
- 生成器的产物 100% 通过静态断言（不合格即拒绝输出）。

### 翻转条件

若 F-AMS-1~5 完成后发现「手写 `.al` 的成本可接受」，则此决策降级为非目标。

## 决策的相互影响

```
D3（槽位骨架）──> 决定 F-AMS-1 的节点模型
D2（:multiagent 内聚）──> 依赖 F-AMS-1 的图模型，但保留短写法
D1（不搬多运行时）──> 去掉 F-AMS-1 的一个自由度（不必为多运行时抽象）
D4（生成层后置）──> 依赖 F-AMS-1~5 全部断言
```

**关键**：D3 与 D2 都指向同一件事——**先建图模型，再把现有声明内聚进去**。
所以执行顺序不变：F-AMS-6 → F-AMS-4 → F-AMS-1 → F-AMS-3 → F-AMS-2/5 → F-AMS-7 → F-AMS-12。

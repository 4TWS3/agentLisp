## 3. CT-LEARNING-01（新规格 + 接线 + 撞硬约束）

### 3.1 现状

| 项 | 值 |
|---|---|
| 契约 | 六栏齐备，期望 235 字节。断言 `recall()` / `write_back()` |
| handler | `recall()` / `write_back()` / `skill_dir()`。**引擎不调** |
| 适配器 | `FileSkillStore` 已在位 |

### 3.2 硬约束（必须先解）

**产物是编译器生成的。运行时写产物 → 触发漂移保护 → 下次编译拒绝覆盖。**

| # | 选项 | 影响 |
|---|---|---|
| A | 写产物**之外**（`./memory/` 或 skill 目录） | **建议**。不与漂移保护冲突 |
| B | 写进产物，接受漂移保护会拦 | 每次学习后必须 `--force` 才能重编译 |
| C | 另设文件格式，编译期读入 | 复杂。需新一轮设计 |

**建议 A。** 理由：漂移保护是刚做的卖点。B 会破坏它。

### 3.3 触发时机（用户已定）

任务失败，或反思产生纠正。

### 3.4 待判项

| # | 项 | 选项 | 我的建议 |
|---|---|---|---|
| 1 | 写入位置（见 3.2） | A / B / C | **A** |
| 2 | 「策略权重」是什么 | A 计数（同签名出现次数）<br>B 规则优先级<br>C 数值权重 | **A**。可确定性断言 |
| 3 | 是否用 LLM | A 不用（纯计数 + 阈值）<br>B 用 LLM 归纳教训 | **A**。用 LLM 即非确定性 |
| 4 | 何时可见 | A 计数达 N 次才进检索<br>B 立即 | **A**。N 默认 2（经验值） |

### 3.5 建议的契约期望

```
给定 (deflearning-agent x :skill-dir "./skills")：
1. 任务失败一次 → recall() 不含该教训
2. 同一失败签名出现 2 次 → recall() 含该教训
3. 写入发生在 skill_dir，产物的 sha256 不变
反证：去掉 :pattern → recall() 返回空，且无写入
```

### 3.6 判据

- 产物指纹在学习前后**不变**（这条同时验漂移保护）；
- 阈值 N 可配；
- 不用 LLM 时有确定性断言；用 LLM 时另立口径。

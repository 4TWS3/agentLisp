# 规格：AMS 特性向 agentLisp 的能力抽取与重构（F-AMS）

> 目的：使 agentLisp 自足，从而 AMS 不再作为并行工具存在。
> 性质：**能力轴抽取 + 重新设计**。不是代码搬迁。
> 基线：agentLisp `7f2d724` · AMS `bd68ad2`（2026-09-20 冻结）
> 日期：2026-10-14

---

## 0. 导读

本文不按 AMS 模块切分。因为模块边界与能力边界不重合。
本文按**能力轴**抽取：先问「要什么能力」，再问 agentLisp 该怎么做，最后才问 AMS 哪段可参考。

每个特性一个编号 `F-AMS-n`，四条固定栏位：来源、必要性、归属、重构设计。
末尾给判据、落地阶段、风险、未验证。

## 1. 方法论：判定顺序与判据

### 1.1 判定顺序（固定，不可跳）

| 步 | 问题 | 不做什么 |
|---|---|---|
| 1 | 这个能力要吗 | 不看 AMS 代码 |
| 2 | 归编译期还是运行期 | 不定实现 |
| 3 | agentLisp 该怎么表达 | 不抄 AMS |
| 4 | 哪段可参考 | 只参考，不搬 |

**为什么顺序固定**：先看代码就会被代码结构带走。AMS 的模块划分是它自己的历史产物。

### 1.2 五条判据（每条可测）

| # | 判据 | 怎么判 |
|---|---|---|
| C1 | 确定性 | 编译期不得调 LLM。违反即失败 |
| C2 | 归属 | 编译期的事不在运行期做，反之亦然 |
| C3 | KV 对齐 | 动态内容不得混进静态段 |
| C4 | 一处实现 | 同一判断不得两处写 |
| C5 | 可验证 | 每个行为须有机器可判的判据 |

### 1.3 三个归属选项

| 归属 | 含义 |
|---|---|
| 编译期 | `.al` → 产物。必须确定性 |
| 运行期 | `BaseHarnessV2` 执行。可含 LLM |
| 不归 agentLisp | 属设计期或外部环境。显式划出 |

## 3. 特性规格

### F-AMS-1 工作流图

| 栏 | 内容 |
|---|---|
| 来源 | AMS `core/compiler/graph_assembler.py`（195 行）的 4 种拓扑算子：sequential / edge / conditional-loop / conditional-edge |
| 必要性 | 必须。缺此则多步骤编排只能写进提示文本，引擎不执行 |
| 归属 | 编译期 |
| 重构设计 | 拓扑**升为语言构造**，不学 AMS 的「数据层」形态 |

**重构理由**：AMS 把拓扑做成 12 个 primitive + 4 个 mode 的 YAML 数据层，再由 `composes_from` 组合。
原因是 AMS 的 spec 是数据。agentLisp 有编译器，**数据层可以升为语法**。升上去后：
引用完整性、环检测、入口唯一性都在编译期拦，不需要运行期再查。

**新构造（草案）**：

```
(:workflow
  :entry plan
  :nodes ((node plan  :type agent)
          (node calc  :type computation :handler "m.f")
          (node judge :type evaluator))
  :topology ((sequential (plan calc))
             (conditional-loop :nodes (calc judge) :while "<0.85" :max-rounds 3)))
```

**与 `:multiagent` 的关系**：二者不并存。`:workflow` 是单 agent 内部的多步骤；
`:multiagent` 是多 agent。**同一文件内二者互斥**，编译期拦。此项须你确认。

**判据**：
- 引用了不存在的节点 → 编译期失败，退出码 1；
- 双入口 → 编译期失败；
- 环未显式声明 → 编译期失败；
- 产物含节点表与边表，运行期可读。

### F-AMS-2 确定性节点接线

| 栏 | 内容 |
|---|---|
| 来源 | AMS `IRNode` 的 `handler` / `handler_init` / `handler_input` / `output_fields` 四个字段，`core/ir/models.py` |
| 必要性 | 必须。缺此则确定性计算步骤无法表达 |
| 归属 | 编译期校验格式；运行期校验存在性 |
| 重构设计 | 分两层，不混 |

**重构理由**：AMS 只写字符串 `"module.function"`，无编译期校验。写错只在运行时报错。
agentLisp 有静态断言，应把**能静态判的静态判**：

| 层 | 校验内容 | 时机 |
|---|---|---|
| 编译期 | 格式（`模块.函数` / `模块.类.方法`）、非空、不与保留名冲突 | 立即 |
| 运行期 | 模块可导入、函数可调用、签名与 `output_fields` 匹配 | 首轮 |

**已知代价（须登记）**：编译器读不到 Python 函数。存在性只能运行期判。
这是「约束冲突时先查本质还是偶然」的一个实例：产物要被独立部署 ⇒ 运行期判是本质，非偶然。

**判据**：
- 格式错 → 编译期失败；
- 模块不存在 → 首轮运行抛可读错误，含「发生了什么 + 为什么 + 怎么办」；
- `output_fields` 中的名字必须出现在节点声明的输出里，否则编译期失败。

### F-AMS-3 状态与上下文传递

| 栏 | 内容 |
|---|---|
| 来源 | AMS `spec.state.fields`（具名字段 + 类型 + 默认值）与 `output_fields` 映射 |
| 必要性 | 必须。缺此则确定性节点的产物无法流到下一步 |
| 归属 | 编译期声明；运行期持有 |
| 重构设计 | 声明 + **编译期流校验** |

**重构理由**：AMS 声明字段，但**不校验**「某节点产出 X，下一节点是否真的用得上 X」。
agentLisp 可加一条 AMS 没有的校验：**字段可达性**。

**新构造（草案）**：

```
(:state :fields ((metrics :type dict)
                 (stage   :type str :default "")))
```

**新增编译期断言**：
- 每个字段至少被一个节点写、或被一个节点读。无人读写的字段 → 警告；
- 节点读的字段必须已被上游节点写过，或已声明默认值。否则 → 失败。

**这条断言是 AMS 没有的。** 它把「忘了接线」变成编译期错误。

**判据**：
- 声明字段后，产物含 `STATE_FIELDS`，运行期可读；
- 读未声明字段 → 编译期失败；
- 读上游未写的字段且无默认值 → 编译期失败。

### F-AMS-4 模式依赖与组合校验

| 栏 | 内容 |
|---|---|
| 来源 | AMS `PatternResolver.resolve_dependencies`（级联失活，fixpoint）+ `validate_composition`（3 条规则：存在性 / `incompatible_with` / `requires` 链） |
| 必要性 | 必须 |
| 归属 | 编译期 |
| 重构设计 | 依赖图移到编译期，删除运行期失活 |

**重构理由（关键）**：AMS 的「依赖未满足 → 模式失活」是**静默降级**。
用户选了 pattern，得到的是「没生效 + 一条 deactivated 记录」。这违反「降级可以，静默降级不行」。

agentLisp 现有 `GROUPS`（互斥组）在**运行期 `on_init`** 才报错。这也是错的时机。

**重构方案**：把两类关系都升到编译期：

| 关系 | 语义 | 现状 | 改后 |
|---|---|---|---|
| 互斥 | 同组只能选一个 | 运行期 `on_init` 抛错 | **编译期失败** |
| 要求 | A 需要 B 在场 | 无 | 编译期：缺 B 则失败，不静默失活 |
| 蕴含 | 选了 A 自动带上 B | 无 | 编译期：自动补齐，并在产物里记录补齐项 |

**这条同时修掉 F-AMS-6 的一半根因。**

**判据**：
- 同组两个 kind → 编译期失败，错误信息点名双方；
- A 要求 B 而 B 缺失 → 编译期失败（不得静默失活）；
- 自动补齐的 kind 出现在产物中，且有一条 warn 级信息说明来源。

### F-AMS-5 节点级提示与插值

| 栏 | 内容 |
|---|---|
| 来源 | AMS `IRNode.prompt` + `prompt_file`；`tool_template` 的 `{param}` 占位符 |
| 必要性 | 必须 |
| 归属 | 编译期 |
| 重构设计 | **受 KV 对齐约束的插值** |

**重构理由（本规格最紧的一条）**：agentLisp 的硬约束是静态段先于动态段（`ERR_KV_ALIGNMENT_VIOLATION`）。
节点级插值天然把动态内容焊进静态段。AMS 无此约束，故不能照抄。

**规则（新增编译期断言）**：

| 规则 | 说明 |
|---|---|
| R1 | 插值变量只允许出现在节点提示的**动态段** |
| R2 | 节点提示拆两段：`:static` 与 `:dynamic`。`:static` 参与 KV 前缀 |
| R3 | 动态段里的变量必须来自 `:state` 已声明字段 |
| R4 | 变量语法固定为 `{field}`。未知字段 → 编译期失败 |

**判据**：
- 在 `:static` 段写 `{field}` → 编译期失败（违反 R1）；
- 变量引用未声明字段 → 编译期失败（违反 R3）；
- 反证：把变量移到动态段，编译通过。

### F-AMS-6 模式行为槽位（架构重构）

| 栏 | 内容 |
|---|---|
| 来源 | AMS 的 pattern 模型：pattern 以 `workflowModification` / `structure.components` / `configuration` / `guardrails` **四类机器字段**驱动编译 |
| 必要性 | **必须。这是根因修复，不是新功能** |
| 归属 | 运行期 |
| 重构设计 | 把「kind 工厂」改为「行为槽位」 |

**问题（本规格最重要的一条）**：

agentLisp 现在的模式模型是 `kind → handler 类`。21 个 kind 各自一个类。
结果是：**类可以存在而行为不发生**。实测：21 个 kind 中，接线消费 13 个，仅声明 8 个。

`HANDLERS[kind]` 存在 ⇒ `LANDED` 通过 ⇒ 文档可写「已落地」。**但引擎从不调用它。**

**重构方案**：一个 pattern 在产物里声明它**占用哪些行为槽位**。

| 槽位 | 谁调用 | 语义 |
|---|---|---|
| `before_turn` | ReAct 循环每轮前 | 改上下文 |
| `on_tool_call` | 每次工具调用前 | 拦/改 |
| `after_turn` | 每轮后 | 改结果 |
| `verify` | 观察值判定 | 门控 |
| `order` | 工具排序 | 重排 |
| `budget` | 轮次/预算 | 限额 |
| `evaluate` | 评估门 | 判分 |
| `orchestrate` | 下一动作选择 | 编排（见 F-AMS-7） |

**新判据（替换 A11 的现有口径）**：

> 一个 kind 只有在其产物声明了**至少一个行为槽位**、且有对应的运行时测试断言该槽位**被调用**时，
> 才算「已落地」。只声明不占槽位的 kind 必须登记为 `declaration-only`。

**为什么这是重构而不是补丁**：它让「声明了却不发生」在机器上不可能。
现在 8 个仅声明 kind 的问题，源不在实现不足，**在模型缺少这个维度**。

**判据**：
- `LANDED` 只收「占用槽位 + 有行为测试」的 kind；
- 每个 kind 的契约必须写明它占用的槽位；
- 判据脚本核对：`LANDED` 中每个 kind 的槽位集合非空。
